# クイック記録 設計案

> 2026-11-02 / ステータス: CEO レビュー待ち
> 方針: [STRATEGY.md](../../STRATEGY.md) §2「撮って、ひとこと話すだけ。旅が終わると、AIが旅行記にしてくれる。」

## 1. 現状の問題

3スポットの旅を1つ記録するのに **約19画面** を通る。

```
旅の基本情報（タイトル・都市・人数・同行者）
└ スポットごとに ×3
   写真 → 位置を選択 → スポット内容（カテゴリ・滞在時間…） → 感想を話す → 次へ
└ 旅の総括 4問（安全・移動・コツ・心に残った瞬間）
└ カバー写真 → 投稿前の確認 → 公開
```

- 旅の最中に「位置を選ぶ」「カテゴリを選ぶ」が毎回求められ、現地では面倒で続かない
- 記録の報酬（読める旅行記）が最後まで出てこない

## 2. 新しい体験：3つの場面に分ける

| 場面 | いつ | ユーザーがやること | 所要 |
|---|---|---|---|
| ① 撮る・話す | 旅の最中（現地） | 📷 を押して撮る → 🎙 を押してひとこと話す | 1スポット 10秒 |
| ② 整える | 移動中・宿・帰宅後 | 場所の候補をタップで確定（任意） | 1スポット 3秒 |
| ③ 旅行記にする | 旅の終わり | 「旅行記をつくる」を押す → AIが日記調にまとめる → 共有 | 1分 |

### ① 撮る・話す（旅の最中ホーム）

```
┌──────────────────────────┐
│ 11月の京都  ・ 2日目        ⋯ │  ← タイトルは自動（月＋最初の都市）、後で変更可
├──────────────────────────┤
│ 10:12  伏見稲荷大社            │
│ [写真]  「朝7時、人が少なくて   │
│          鳥居がきれい」         │
│ 12:40  📍場所を確認  ・ 未確認   │  ← GPSだけ保存済み。場所名は後で
│ [写真]  「にしんそば美味しい」   │
│                                │
│                                │
│     ┌─────┐   ┌─────┐       │
│     │  📷  │   │  🎙  │       │  ← 大きな2ボタン。片手で押せる位置
│     └─────┘   └─────┘       │
│        撮る       話すだけ      │
└──────────────────────────┘
```

- 📷: カメラ / ライブラリ → 保存と同時に GPS（なければ写真の EXIF）と時刻を記録 → そのまま「ひとこと話しますか？」（スキップ可）
- 🎙: 押している間だけ録音 → ブラウザ内で文字起こし（無料）→ 直前の写真に付く、または写真なしの記録として残る
- **入力必須項目なし**。カテゴリ・滞在時間・評価は聞かない

### ② 整える（あとで）

```
┌──────────────────────────┐
│ 場所を確認（2件）               │
├──────────────────────────┤
│ [写真] 12:40                   │
│   ○ 松葉 本店           80m    │  ← 既存の位置候補 API（GPS→近くの場所）
│   ○ 南座               120m    │
│   ○ 自分で入力                 │
└──────────────────────────┘
```

- 1件ずつタップで確定。やらなくても旅行記は作れる（場所名なしの記録は時刻と都市で扱う）
- プレミアム案「AIが自動で場所を特定」はここを自動化する（今回は対象外）

### ③ 旅行記にする

```
┌──────────────────────────┐
│ 11月の京都                     │
│ 2026.11.1 – 11.2 ・ 6スポット   │
├──────────────────────────┤
│ 1日目                          │
│ [写真]                         │
│ 朝7時の伏見稲荷は、まだ人もまば  │
│ らで、朱色の鳥居がどこまでも続い  │
│ ていた。…                      │
│ [写真]                         │
│ 昼は南座の向かいで、にしんそば。  │
│ …                              │
├──────────────────────────┤
│ [ 公開して共有 ]  [ 自分だけ ]   │
│  LINE / X / リンクをコピー       │
└──────────────────────────┘
```

- AI（Haiku 5.5）が、各記録の「時刻・場所・ひとこと」だけを材料に日記調の文章を作る。**話していないことは書かない**よう指示する
- 生成後に本文を手直しできる
- 公開ページの下部に「GlobeHubで旅行記をつくる」導線（共有が新規獲得になる）

## 3. 既存機能の扱い

| 既存 | 扱い |
|---|---|
| 旅の基本情報（人数・同行者） | 開始時は聞かない。旅行記の生成前に任意で1画面 |
| スポット詳細（カテゴリ・滞在時間 等） | 各記録の「詳しく書く」から任意で開ける形で残す |
| 旅の総括 4問 | 旅行記の生成後に「ふりかえりを足す」として任意化 |
| カバー写真 | 旅行記の1枚目を自動で採用、変更可 |
| 計画からの記録（PlanRecorder） | 変更しない |

コードは削除せず、入口を新フローに付け替える。

## 4. 実装範囲

| 区分 | 内容 |
|---|---|
| DB | Trip に `journalText`, `journalGeneratedAt` を追加（既存の Spot の lat/lng・写真・impressionRemarks をそのまま使う） |
| API | `POST /api/trips/:id/journal`（旅行記生成）。予算上限は既存 budgetGuard |
| 画面 | 旅の最中ホーム / 撮る・話すシート / 場所の確認 / 旅行記ビュー（公開ページ兼用） |
| 入口 | 記録タブ・登録直後 → 「旅を始める」1タップ |

AIコスト: 旅行記1本あたり約 ¥0.3（Haiku 5.5、10スポット想定）

## 5. 確認したい点

1. この3場面の流れで進めてよいか
2. 旅行記の公開は「生成後に公開/自分だけを選ぶ」でよいか（初期値は「自分だけ」を推奨）
3. 料金プラン実装まではAI旅行記を全員無料（月の上限は budgetGuard で管理）でよいか

## 6. 検証方法

ローカルでは Windows のアプリ制御で画面ビルドが動かないため、Render に確認用サービスを1つ追加し、そこで画面を確認する。
